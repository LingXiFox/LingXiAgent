# ADR-0003：插件启停状态是配置，不进会话事件日志

状态：已采纳（2026-10-20，随 Phase 2 闭环落地）

## 背景

D3 把「事件日志是唯一真相源」限定在**会话与 Run**上。插件是否安装/启用不属于会话历史：它跨会话存在、
不是某次执行的事实，而且恢复流程只重放 `runCreated/entryRecorded/...` 这类事件。若把插件状态写进
`events.jsonl`，会话日志会混入与之无关的控制面变更，STORE-008 的重放语义也要为它开口子。

## 选择

插件注册表是**独立持久配置**：数据目录下的 `plugins.json`，原子写入（临时文件 + rename），
记录 `bundleID / version / bundlePath / enabled`。事件日志不出现任何插件记录。
监管者（`PluginCoordinator`）以注册表为唯一真相源决定是否拉起 Host；目录扫描不决定运行。

## 代价与边界

- 多了一份需要保持一致性的存储，但它只描述控制面配置，不参与 Run 的原子性证明。
- 「禁用」的判定顺序固定为：先摘路由（Hook 管线），再停进程（stop → 等待退出 → 必要时 SIGKILL），
  最后写注册表。任何一步失败都以“宁可显示未启用、也不谎报运行中”为准。
- 若将来插件状态需要与其他控制面配置共用事务，再评估合并存储，并作为新 ADR。

## 可逆性

可逆：注册表格式是本地实现细节，未对外承诺；迁移到其他存储不改变 ABI 或生命周期语义。
