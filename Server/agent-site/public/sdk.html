Framework

LingXiPluginSDK

为 LingXiAgent 打造物理进程隔离的高性能原生 Swift 扩展。声明交互式 Slash 命令、扩展模型自主 Tools、感知双核能效与上下文高维指标，在极致安全边界下扩展 Agent 核心能力。

macOS: 14.0+
Linux: glibc 2.34+ (x86_64 / aarch64)
Swift: 6.0+
Xcode: 16.0+

Declaration

import LingXiPluginSDK

Overview

LingXiPluginSDK 是 LingXiAgent 系统的官方扩展开发套件。与简单的提示词包装或脚本解释器不同，LingXiPluginSDK 允许开发者直接使用现代 Swift 编写经由类型安全检查的原生可执行二进制。

在架构设计上，SDK 遵循两大不可动摇的黄金原则：

  • 进程级物理隔离沙箱 (Process Sandboxing)：插件以独立子进程运行，Core 与 Plugin 之间通过标准 IPC（JSON-RPC 载荷）在标准输入输出中通信，绝不使用 dlopen 动态共享内存，彻底封死 API Key 与内存凭据被窃取的通道；
  • “多开放 INFO 感知，少开放执行控制”：插件拥有高维的只读系统感知能力（会话 Token 水位、P-Core / E-Core 双核负载、耗时指标），但严禁篡改 Agent 核心调度机制与会话状态，避免插件凌驾于主驾驶员（Client / TUI）之上。
Note
外部二进制插件编译后只需直接放入工作区 .lingxi/plugins/ 或用户全局目录 ~/.lingxiagent/plugins/，LingXiAgent 即可自动感知、校验清单并在沙箱中按需激活。

Quick Start

只需 3 步，即可完成一个生产级 Swift 插件的开发与部署。

1 创建 Swift Package 并引入 LingXiAgent 依赖 

// swift-tools-version:6.0
import PackageDescription

let package = Package(
    name: "MyFirstPlugin",
    platforms: [.macOS(.v14)],
    dependencies: [
        .package(url: "https://github.com/LingXiFox/LingXiAgent.git", branch: "main")
    ],
    targets: [
        .executableTarget(
            name: "my-plugin",
            dependencies: [
                .product(name: "LingXiPluginSDK", package: "LingXiAgent")
            ]
        )
    ]
)

2 编写 main.swift：实现 LingXiPlugin 协议 

import LingXiPluginSDK

@main
struct MyFirstPlugin: LingXiPlugin {
    var manifest: PluginManifest {
        PluginManifest(
            id: "my-first-plugin",
            name: "小狐狸状态管家",
            version: "1.0.0",
            description: "演示高维系统状态感知与弹出式 TUI 命令",
            capabilities: [.projectRead]
        )
    }

    func activate(context: PluginContext) async throws {
        // 注册 Slash 命令: /fox-status
        context.registerCommand(FoxStatusCommand())
    }
}

struct FoxStatusCommand: PluginCommand {
    let name = "fox-status"
    let description = "弹出查看双核运行负载与会话指标"

    func execute(args: [String], context: CommandExecutionContext) async throws -> PluginCommandResult {
        let pe = try await context.info.getPECoreInfo()
        let ws = try await context.info.getWorkspaceInfo()

        let card = """
        • 工作区路径: \(ws.rootPath)
        • Git 当前分支: \(ws.currentGitBranch ?? "无")
        • P-Core 状态: \(pe.pCoreRole)
        • E-Core 状态: \(pe.eCoreRole)
        • 思考深度等级: \(pe.reasoningEffort)
        """

        // 开发者可选择 .modal 弹出式浮层展示，或 .inline 行内展示
        return .message(card, presentation: .modal, title: "双核健康体检")
    }
}

3 编译并一键投递二进制到插件目录 

# 编译 Release 二进制
swift build -c release

# 投递到 LingXiAgent 全局插件目录（或当前项目 .lingxi/plugins/）
mkdir -p ~/.lingxiagent/plugins
cp .build/release/my-plugin ~/.lingxiagent/plugins/

# 在 TUI 终端中输入 /plugins 查看加载状态，敲击 /fox-status 体验居中弹出窗口！

Topics

Plugin Lifecycle & Manifest

P protocol LingXiPlugin

外部插件的入口协议。声明插件元数据，并在 activate(context:) 中注册 Commands、Tools 与 Hooks。

›
S struct PluginManifest

包含插件 ID、显示名称、语义化版本号、作者以及申请的权限能力列表。

›
E enum PluginCapability

声明插件所需的权限能力：.projectRead（只读工作区）、.projectWrite、.networkAccess 等。

›

Slash Commands & Presentation

P protocol PluginCommand

扩展用户在终端交互输入框直接敲击的斜杠命令（例如 /fox-info），支持入参、别名与分类。

›
E enum PluginPresentationStyle

控制命令执行结果在客户端呈现的物理形态：.modal（居中独立弹出浮层，支持上下滚动与 Esc 关闭）或 .inline（行内时间轴卡片）。

›
E enum PluginCommandResult

命令执行的返回值：.message(text, presentation:, title:) 本地卡片免消耗 Token 输出，或 .prompt(text) 动态构造指令唤醒 Agent 思考。

›

High-Dimensional Context Sensing (Read-Only Info Hub)

S struct PluginInfoHub

系统的全局只读高维感知中枢。通过 context.info 访问，严密受权限系统保护，只读不写。

›
M func getPECoreInfo() async throws -> PECoreInfo

获取 P-Core（决策核）与 E-Core（执行核）的双核协同分工状态、思考等级、双核耗时比与后台任务水位。

›
M func getContextState() async throws -> ContextStateInfo

感知当前会话的模型 ID、Token 累计消耗、上下文窗口使用率、轮次数及是否触发过滑动窗口压缩。

›
M func getPerformanceInfo() async throws -> PerformanceMetricsInfo

获取首字延迟 (TTFT)、思考耗时、工具执行总耗时及 Provider 接口平均延迟指标。

›
M func getWorkspaceInfo() async throws -> WorkspaceSnapshotInfo

获取当前工程工作区根路径、当前 Git 分支名、未暂存脏文件计数与 Core 内核版本号。

›

Extending Autonomous Model Tools

P protocol PluginTool

声明供大模型在 ReAct 思考与工具循环中自主决策调用的 Native Tool。需提供 JSON Schema 参数规范。

›
S struct ToolExecutionContext

工具调用的执行上下文，携带调用 ID、会话 ID、InfoHub 访问句柄及结构化 Logger。

Security & Sandboxing

为杜绝恶意插件或第三方依赖危害开发者的工作站安全，LingXiAgent 在内核层筑牢了四大安全防线：

防线一 · 物理地址空间隔离

插件以独立子进程运行，杜绝使用 dlopen 加载未知动态库。插件无法读取主进程堆栈与环境变量中的任何 API Key。

防线二 · 零信任清单声明

插件必须在 Manifest 中显式声明所需 Capabilities。未申请的敏感操作直接被内核权限仲裁器（PermissionEngine）即时拦截。

防线三 · IPC 强类型契约

Core 与 Plugin 仅通过标准输入输出传输符合 Swift Codable 契约的数据包。单次调用超时（默认 10s）自动截断，防止子进程卡死。

防线四 · 权力边界与纯读原则

SDK 严格遵循“重 INFO，轻 Control”。插件无法随意操纵主循环状态机，确保 Client 前端始终拥有唯一最高驾驶权。

Important
严禁在插件中尝试读取 ~/.ssh、~/.aws 或未声明的项目外部路径。任何违反 Capability 声明的越界访问都将被 LingXiAgent 记入安全审计日志并立即停用该插件。
Language-Agnostic IPC

JSON-RPC IPC 跨语言底层通信协议规范

虽然官方提供了基于 Swift 6.0 的强类型 SDK，但 LingXiAgent 的插件内核基于标准进程隔离设计。这意味着开发者可以使用 Rust、Go、Python、C++ 或任意语言编写独立二进制插件，只要遵循以下标准输入输出（stdio）JSON-RPC 契约即可无缝接入。

1. 通信机制与生命周期

  • 载体通道：Core 主进程通过标准管道（stdin / stdout）与插件进程通信，无须开启网络端口；
  • 报文分帧：单次 RPC 交互传输标准 JSON 对象，以换行符（\n）为分包定界符；
  • 请求结构：{"id": "...", "method": "...", "params": {...}}
  • 响应结构：{"id": "...", "result": {...}, "error": null}

2. 核心 RPC 方法与数据载荷

Method plugin.initialize (进程启动握手) 
// 1. Core 发送初始化握手请求
{"id": "init-1", "method": "plugin.initialize"}

// 2. 插件子进程回包宣告清单与贡献项
{
  "id": "init-1",
  "result": {
    "manifest": {
      "id": "my-rust-plugin",
      "name": "Rust 诊断扩展",
      "version": "1.0.0",
      "capabilities": ["projectRead"]
    },
    "tools": [
      {
        "name": "rust_audit",
        "description": "调用 Rust 本地分析引擎进行安全体检",
        "inputSchema": "{\"type\":\"object\",\"properties\":{\"path\":{\"type\":\"string\"}}}"
      }
    ],
    "commands": [
      {
        "name": "rust-info",
        "description": "弹出查看 Rust 插件运行状态",
        "category": "Diagnostics"
      }
    ]
  },
  "error": null
}
Method command.execute (执行斜杠命令) 
// 1. 用户在终端输入 /rust-info --verbose
{
  "id": "cmd-42",
  "method": "command.execute",
  "params": {
    "commandName": "rust-info",
    "arguments": ["--verbose"],
    "sessionID": "sess-abc-123"
  }
}

// 2. 插件返回展示模式（支持 "modal" 居中弹出浮层 或 "inline" 行内卡片）
{
  "id": "cmd-42",
  "result": {
    "isPrompt": false,
    "text": "• 引擎版本: v1.82 (Rust native)\n• 内存常驻: 4.2 MB\n• 安全评分: 98/100",
    "presentation": "modal",
    "title": "Rust 审计诊断报告"
  },
  "error": null
}
Method tool.call (模型自主调度工具) 
// 1. 大模型在 ReAct 循环中自主调用插件工具
{
  "id": "tool-88",
  "method": "tool.call",
  "params": {
    "toolName": "rust_audit",
    "arguments": "{\"path\":\"Sources/\"}",
    "sessionID": "sess-abc-123",
    "toolCallID": "call_9901"
  }
}

// 2. 插件子进程执行本地逻辑并返回纯文本或 JSON 结论
{
  "id": "tool-88",
  "result": "{\"issues\": 0, \"scannedFiles\": 42, \"status\": \"clean\"}",
  "error": null
}
