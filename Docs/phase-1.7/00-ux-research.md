# Phase 1.7 UX 研究与工作台定位

- 状态：实现与验收进行中
- 分支：`rewrite/3.0`
- 范围：项目工作区主视图、项目/会话/文件树、Agent 时间线、底部 composer、默认收起的辅助面板
- 不在范围：仪表盘、营销式首页、第二套节点编辑器、复杂多 Agent 编排界面

## 1. 要解决的问题

Phase 1.6 的工作台已经能观察和干预 Agent，但入口仍以画布为中心，且运行没有真正绑定一个项目目录。对日常使用者，这会带来四个具体问题：

1. **起点错误**：打开应用先看到空画布，用户得先理解节点、连线和组合才能做一次普通任务。
2. **上下文断裂**：Agent 读写的是应用默认工作区，不是用户正在开发的项目；文件树、Git、diff、规则都无从展示。
3. **会话不连续**：每次运行像一次性演示，之前的消息、交付和运行记录不构成一个可持续的会话。
4. **干预不透明**：权限、模型、暂停、配置修订混在画布参数里，普通用户看不到“这次运行到底被允许做什么”。

Phase 1.7 的目标不是把画布做强，而是把**项目 → 会话 → Agent 运行**这条主线做顺；画布仍是高级用户的结构编辑视图。

## 2. 设计依据

设计沿用四类成熟交互，不引入新概念：

| 来源模式 | 采纳部分 | 不采纳部分 |
| --- | --- | --- |
| IDE | 左侧项目/文件树、版本化文件编辑、Git 状态与 diff | 多标签编辑器、完整 IDE 功能 |
| 终端 Agent 工具 | 底部 composer、连续会话、权限模式、运行中纠偏 | 纯命令行界面、不可观察的黑盒 |
| ComfyUI | 自由节点画布、左侧节点库、底部日志、运行/终止 | 把项目文件或会话做成节点 |
| 代码评审工具 | 右侧按需打开的 diff/规则/配置面板 | 常驻三栏、仪表盘式统计 |

关键取舍：**默认视图是工作台，画布是一等视图但不是默认入口**。普通用户不需要看到图结构就能完成任务；高级用户仍可切换到画布编辑同一份工作流。

## 3. 信息架构

```
应用
├─ 工作台（默认）
│  ├─ 左侧栏（可收起）
│  │  ├─ 打开项目 / 最近项目
│  │  ├─ 会话列表（新建会话 / 新建团队）
│  │  ├─ 项目文件树与搜索
│  │  └─ Git 摘要
│  ├─ 中央
│  │  ├─ 总览标签
│  │  ├─ 每个 Agent 的标签
│  │  ├─ 时间线（消息、工具、增量输出、审批）
│  │  └─ 底部 composer（权限模式、模型、推理、发送/终止/指令）
│  └─ 右侧辅助面板（默认关闭）
│     ├─ 文件（版本检查保存、diff）
│     ├─ Git（变更、最近提交）
│     ├─ 规则（AGENTS.md 链）
│     └─ 运行配置（预览、应用）
└─ 画布（高级视图）
   ├─ 节点库
   ├─ 自由画布
   ├─ 运行/终止、校验、保存
   └─ 底部实时日志
```

## 4. 交互原则

1. **先项目，后会话，再运行**：没有项目就没有会话；会话保存工作流草稿；每次运行绑定会话与项目。
2. **默认收起，按需展开**：右侧辅助面板默认关闭，避免工作台退化成三栏后台；文件树在左栏折叠区内按需展开。
3. **只显示真实事件**：时间线只渲染 Rust 事件、模型增量与工具结果；没有运行时显示空态，不伪造“思考中”或进度条。
4. **权限可见**：composer 始终显示当前权限模式；YOLO 有常驻警告，说明自动执行的真实副作用与仍会拦截的边界。
5. **高频交互留在前端**：画布拖动、缩放、选中和节点内输入不逐帧调用 Rust；保存、运行、校验、文件读写才过 IPC。
6. **双向可定位**：工作台点击“定位节点”进入画布并选中对应节点；画布选中 Agent 后可回到工作台对应标签。
7. **不新增第二编辑器**：工作台不提供节点连线；需要改结构时切到画布，运行中结构锁定。
8. **中文优先，标识稳定**：界面中文，节点 kind、端口名、参数名、事件字段保持英文稳定标识。

## 5. 被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| 纯聊天首页，项目藏在设置里 | 文件、Git、规则与权限都失去可见位置，退化成通用聊天壳 |
| 把项目目录画成节点 | 文件树是导航，不是执行图；会强迫普通用户理解图结构 |
| 右侧面板默认常开 | 挤占时间线，接近仪表盘；违反“极简节点编辑器 + 聚焦工作台”的约束 |
| 每次任务新开窗口 | 会话连续性和运行历史被切断，也无法复用项目绑定 |
| 工作台里再放一套节点编辑器 | 两套编辑器状态同步复杂，且与 ComfyUI 布局冲突 |
| 用前端模拟 Agent 进度 | 与“不伪造交互”冲突，无法作为验收证据 |

## 6. 验收关注点

- 打开真实已存在文件夹后，项目、文件树、Git 与会话都绑定到同一根目录。
- 新建会话生成默认 `core.project_workspace → core.agent → core.log` 工作流，可直接运行。
- 同一会话连续两次运行保留历史并复用同一 Agent 节点。
- 工作台与画布双向定位不重启运行。
- 文件保存使用版本检查，过期写入被拒绝；越界路径与符号链接逃逸被拒绝。
- Ask / Workspace / YOLO 三种模式在真实 Rust 执行层生效，并可审计。
