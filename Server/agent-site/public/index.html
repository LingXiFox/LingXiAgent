Core Engineering

为高强度编码设计的六大原生杀手特性

⚡

macOS · Linux · Windows 原生跨平台引擎

纯 Swift 原生编译，不依赖 Node.js 或 Electron 运行时。底层独立模块 LingXiPlatform 统一抽象 Darwin、Linux（含 Bubblewrap 进程沙箱）与 Win32 控制台：VT100 虚拟终端、%PATHEXT% 解析与进程树级联终止。三端均有官方预编译发布包，Intel Mac 与 AArch64 Linux 走源码构建。

🛡️

宿主感知的请求画像 (Client Fingerprint)

ClientFingerprint 按渠道动态生成出站 User-Agent 与伴随请求头：操作系统与架构字段取自真实宿主，协议专属 Header（如 originator、anthropic-beta、X-Goog-Api-Client）按 endpoint profile 注入，避免中转客户端硬编码其它平台字符串。

🔑

官方订阅渠道与自定义 API 配置分离

ChatGPT Plus/Pro（Codex OAuth）、Claude Code 订阅、Google Antigravity / Gemini Code Assist、xAI Grok 订阅等官方渠道内置于运行时契约，无需写入用户配置；DeepSeek、OpenAI 兼容端点、Ollama 等自定义 Provider 走独立的 providers.json。两条通道互不污染，升级时不会覆盖你的自定义配置。

🧠

P-Core / E-Core 上下文双核分工

P-Core 决定什么留在模型请求上下文里（稳定前缀、递增上下文、E-Core 索引投影），淘汰由 P 侧保留策略决定；E-Core 保存被 page-out 的完整上下文对象，供引用索引、精确还原与语义召回。E-Core heat 只服务于召回与可观测性，不驱动 P-Core eviction。

🛠️

多语言 LSP、代码图谱、格式化引擎与 ACP 标准

内置多语言 LSP 语义矩阵、原生代码知识图谱（架构分层与调用链追踪）、对标 OpenCode 的多语言代码格式化引擎；原生实现 ACP 协议直连 Zed IDE；全功能兼容 MCP 生态与 Skills 扩展。

🔒

本地凭据库 · 无官方中转服务

凭据存放在本机数据目录下的 credentials.vault：AES-256-GCM 认证加密、机器绑定密钥、可选口令派生、文件权限 0600（macOS Keychain 中的历史条目仅做一次性迁移读取）。会话与代码留在本机，推理请求直连你所配置的 Provider 端点；网站与客户端都不存在官方中继服务，仅模型目录从 models.lingxifox.cn 拉取公开数据。

Context Architecture

P-Core 与 E-Core 的当前职责边界

P-Core 决定什么留在模型请求的上下文里；E-Core 保存被 page-out 的完整对象并可随时精确还原。淘汰由 P 侧保留策略决定，E-Core heat 只用于召回排序与可观测性，不驱动 P-Core eviction。

P-Core

PCoreContextEngine

Prompt-resident reasoning context：组装真正发给模型的请求内容，并按 P 侧保留策略决定哪些片段留在窗口内。

  • ▸ Stable Prefix：系统与前缀内容，命中上游 Prompt Cache
  • ▸ Growing Context：本轮会话增量与工具轨迹
  • ▸ E-Core Index Projection：仅投影引用与摘要，不含完整对象
  • ✕ 不由 E-Core heat 触发淘汰

E-Core

ECoreObjectStore · ECoreReference

Context object store / recall：被 page-out 的完整对象在此持久化，模型按需通过 ID 精确取回或语义检索。

  • ▸ Offloaded full objects：完整工具输出与会话产物
  • ▸ References / index：面向 P-Core 的紧凑投影
  • ▸ Exact restore：按 ContextObjectID 原样还原
  • ▸ Semantic recall：检索层按相关性与 heat 排序

# 1. 快速上手 (Getting Started)

LingXiAgent 为 macOS arm64、Linux x86_64、Windows x86_64 发布预编译安装包（当前最新 release：v1.1.0，权威来源为 GitHub Releases）。安装只需一条命令，即可自动完成平台与架构探测、可执行文件（lingxiagent、LingXiTUI、LingXiCoreHost）与资源包部署，并配置环境变量。Intel Mac 与 AArch64 Linux 需从源码构建。

步骤一：一键自动安装

macOS / Linux (Bash/Zsh · 官方推荐):
$ curl -fsSL https://agent.lingxifox.cn/install.sh | bash
Windows (PowerShell):
> irm https://agent.lingxifox.cn/install.ps1 | iex

步骤二：刷新终端并首次启动

# 刷新终端配置环境（或重新打开一个终端窗口）
$ source ~/.zshrc

# 立即启动终端交互界面
$ lingxiagent
提示： 首次启动时若未配置任何账号，可在 TUI 中输入 /connect，或在命令行执行 lingxiagent-ops auth login <product>（lingxiagent-ops auth list 查看可登录渠道）。

# 2. 终端 TUI 使用指南 (TUI Usage)

LingXiAgent 的终端界面为原生 Swift 渲染（经 LingXiPlatform 的终端抽象对接真实 TTY），采用双栏式布局，支持思考流折叠、代码 Patch 高亮审查与键盘一键导航。帧率与延迟取决于终端模拟器与宿主环境，本页不给出未实测的数字。

# 3. 提供商与认证体系 (Providers & Auth)

LingXiAgent 确立了“官方内置渠道与自定义渠道物理隔离”的核心架构。内置渠道无需也不允许写入用户配置文件，确保升级平滑无污染。

官方订阅登录命令 (OAuth 认证)

# 1. 登录 OpenAI ChatGPT Plus / Pro 订阅:
$ lingxiagent-ops auth login openai-codex
# 2. 登录 Claude Code 订阅:
$ lingxiagent-ops auth login anthropic-claude-subscription
# 3. 登录 Google Antigravity / Gemini Code Assist:
$ lingxiagent-ops auth login antigravity

自定义 API 提供商配置 (~/.lingxiagent/providers.json)

若想接入 DeepSeek、硅基流动、Ollama 等第三方 API，在配置文件中添加即可：

{
  "$schema": "https://lingxiagent.lingxifox.cn/schema/providers.json",
  "version": 1,
  "providers": {
    "deepseek": {
      "name": "DeepSeek 官方",
      "adapter": "openai-compatible",
      "options": {
        "baseURL": "https://api.deepseek.com/v1",
        "apiKey": "{env:DEEPSEEK_API_KEY}"
      },
      "models": {
        "deepseek-chat": { "name": "DeepSeek V3" },
        "deepseek-reasoner": { "name": "DeepSeek R1" }
      }
    }
  }
}

# 4. 客户端请求画像与指纹 (Client Fingerprint)

访问官方订阅端点时，出站请求需要如实表明客户端形态：ClientFingerprint 按渠道生成 User-Agent 与伴随请求头，其中操作系统与架构字段取自当前真实宿主。本页不承诺任何“绕过风控”的效果；请求画像只描述客户端自身的形态，上游如何对待这些请求由上游决定。

为什么平台字段必须动态读取？

如果客户端运行在 macOS Apple Silicon 上，却上报 Ubuntu 22.04 或 Windows AMD64 的字符串，请求形态就与真实环境矛盾：既可能命中上游按平台划分的协议分支，也让本地排障失去依据。因此 osName / arch / TERM 一律来自 ClientFingerprint.currentPlatform()，不由配置文件硬编码。

动态出站指纹一览

渠道 出站 User-Agent 伴随请求头
OpenAI Codex codex-cli/0.154.0 (darwin; arm64) originator: codex-cli, OpenAI-Beta: responses=v1, chatgpt-account-id
Claude 订阅 claude-cli/2.1.258 (external, cli) anthropic-version: 2023-06-01, anthropic-beta, anthropic-client
Antigravity antigravity/2.9.1 darwin/arm64 X-Goog-Api-Client: antigravity/2.9.1

表中的 darwin/arm64 会随真实宿主变化。客户端版本默认 0.154.0 / 2.1.258 / 2.9.1，可分别通过 CODEX_CLI_VERSION、CLAUDE_CLI_VERSION、ANTIGRAVITY_VERSION 覆盖；Gemini Code Assist 与 xAI Grok 订阅渠道走同一套画像生成逻辑。

# 5. 开放标准：ACP、LSP 与 MCP (Protocols & Extensions)

LingXiAgent 全面拥抱开放标准生态，原生支持 Agent Client Protocol (ACP)、Language Server Protocol (LSP) 以及 Model Context Protocol (MCP)。

⚡ 接入 Zed IDE (ACP 标准协议模式)

执行 lingxiagent-ops acp 启动通用 Agent 后端服务（ACP 属于 ops 入口）。在 Zed 的 settings.json 中配置： 

{
  "assistant": {
    "version": "2",
    "default_model": { "provider": "acp", "model": "LingXiAgent" },
    "providers": {
      "acp": { "command": "lingxiagent-ops", "args": ["acp"] }
    }
  }
}

🔌 MCP 服务器配置 (~/.lingxiagent/mcp.json)

{
  "$schema": "https://lingxiagent.lingxifox.cn/schema/mcp.json",
  "version": 1,
  "servers": [
    {
      "id": "filesystem",
      "transport": "stdio",
      "command": "npx",
      "arguments": ["-y", "@modelcontextprotocol/server-filesystem", "/absolute/path"],
      "enabled": true
    },
    {
      "id": "github",
      "transport": "stdio",
      "command": "npx",
      "arguments": ["-y", "@modelcontextprotocol/server-github"],
      "enabled": true,
      "environment": [
        { "name": "GITHUB_PERSONAL_ACCESS_TOKEN", "credential": "{env:GITHUB_PERSONAL_ACCESS_TOKEN}" }
      ]
    }
  ]
}

凭据字段只接受 {env:VAR} / {vault:...} 引用形式，配置文件里不写明文 token。完整字段见 /docs.html#mcp-ecosystem。

# 6. 常见问题与排错 (Troubleshooting)

Q1: 安装后提示 command not found: lingxiagent？

请确认你的 Shell 配置文件中包含 export PATH="$HOME/.lingxiagent/bin:$PATH"，并执行 source ~/.zshrc（或重新打开终端）。

Q2: TUI 界面字符乱码或布局错位？

建议使用支持 TrueColor 及现代终端协议的终端模拟器，如 Ghostty、WezTerm、iTerm2 或 Kitty，并确保终端字体安装了支持 Nerd Font 或常见等宽编程字体（如 JetBrains Mono、Fira Code）。
