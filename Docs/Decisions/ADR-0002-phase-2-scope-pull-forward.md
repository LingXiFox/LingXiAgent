# ADR-0002：把插件撤销、崩溃隔离与 Hook 生效前移到阶段 2

状态：已采纳（主人 2026-10-20 拍板）

## 背景

`Regression-Cases.md` 的「阶段」列把 PLG-002/003/004/005/006/013/016/018 标为阶段 3，而
`Project-Conventions.md` 第十章把「插件异常隔离与启停撤销的验收」设为进入阶段 4 的门。
主人对阶段 2 第一个交付物的要求是**动态插件闭环**：装载、能力注册与撤销、Hook 拦截、生命周期清理、
崩溃隔离，外加一个真实改变上下文装配的实验插件，并用端到端测试验证真进程与真插件边界。

两者不一致，必须记账，不能口头前移。

## 选择

按主人的范围执行，并把这些行的「阶段」列改为 2、在修订记录里写明前移理由。**不**修改项目书 §七 的
验收标准本身，只调整它落在哪个阶段。

## 同批决定：`security` 类 Hook 本阶段只做「故障即拒绝」

文档要求 `security` 类 Hook 故障时「一律拒绝**并要求人工确认**」，但待答交互的数据模型（`interrupted`
的进入/续跑/超时）在设档里完全未定义。决定：本阶段实现**内核定类别 + 故障即判拒绝**，
「要求人工确认」连同待答交互一起推迟到有交互数据模型的那一轮，不临时造一个隐式接口。

理由：拒绝语义本身不依赖交互层，可以先证明；而人工确认需要一个能被恢复矩阵正确处理的持久状态，
硬凑会同时污染 Hook 与恢复两条线。

## 代价

- 阶段 3 的原定内容变薄，PLG-014（在线恢复只读补跑）仍在阶段 3，不受影响。
- 「security 故障即拒绝」先行落地意味着交互层落地时要回头补「并要求人工确认」，不能把它当成已完成。

## 可逆性

可逆：把行改回阶段 3 即可，但已写的测试与验收记录会留下痕迹，属于文档债而非代码债。
