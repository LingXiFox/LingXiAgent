# ADR-0004：Provider 路由归属、冲突与撤销顺序

状态：已采纳（Phase 3.1）

## 背景

Provider 是动态插件能力。若路由只增不减，禁用插件会留下幽灵模型；若多个插件声明同一模型，
后注册者会静默覆盖前者的路由；若撤销时不区分归属，一个插件的故障可能清掉别人的模型。

## 决定

1. **归属**：`ModelRouter` 以 provider id 为唯一所有者，模型索引指向所属 provider。撤销按 provider id
   精确删除其全部模型，其他 provider 不受影响。
2. **冲突**：`register` 原子且抛错——provider id 重复、模型 id 已被占用（含同次注册内重复）一律整批拒绝，
   不做覆盖，也不留下部分路由。
3. **生命周期归协调器**：`PluginCoordinator` 持有 router 时，启用即注册、禁用即撤销；启用任一步失败
   （路由冲突、Hook、注册表写入）都回滚本次已安装的路由、Hook 与 Host 进程。
4. **禁用顺序**：先写注册表（磁盘拒绝则整个禁用不发生，避免内存与磁盘不一致）→ 摘除该插件的模型路由
   → 取消其在途请求 → 卸载 Hook → 停止 Host。新 Run 在路由摘除后立刻无法解析到该模型。
5. **意外退出**：`terminationHandler` 触发后按同一套作用域清理路由与 Hook，并把注册表置为 `enabled=false`，
   防止重启后自动复活一个反复崩溃的插件。
6. **不自动重试**：本阶段没有熔断/退避；崩溃后由用户显式重新启用。

## 代价

- 崩溃会把 `enabled` 置 false，需要人工重新启用（换取“不自动复活崩溃插件”）。
- 禁用依赖注册表可写；磁盘故障时禁用会失败并保持原状，而不是部分生效。
- 在途请求以 `failed / providerFailure` 收敛，不伪装为取消或成功。

## 可逆性

可逆：路由 API 与清理顺序是本阶段的内部契约；引入租约与熔断时在此之上扩展，不改变归属语义。
