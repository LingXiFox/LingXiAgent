# P15.1 Execution Deadline Gap Audit

审计范围：`LingXiCore` 的 Agent、Session、Provider、Tool、Process、MCP、Subagent、取消、配置和持久化；以及对应的 Swift 测试。结论基于当前源码，不改变 P15 Golden。

## 结论

当前系统已有若干局部 timeout 和 cancellation 机制，但没有统一的 Runtime deadline contract。除短命令外，Provider stream、MCP request、Tool 外部执行和默认 Subagent 都可能缺少最终 terminal boundary。P15.1 的最小收口点应是 Core Runtime 的 deadline policy，加上 Tool/Provider/MCP/Subagent 的调用边界；Agent loop 继续负责编排，不负责 retry 或 fallback。

## Execution Audit

| Execution type / location | 当前状态 | 证据与缺口 |
| --- | --- | --- |
| AgentRun / `AgentRuntime`, `SessionRuntime` | 已有但不足 | `SessionRuntime` 用 Task 承载 turn，`AgentRuntime.cancelAgentRun` 能取消并落盘；没有统一 run deadline、取消后的等待/cleanup confirmation，默认 Agent turn 无 deadline。 |
| Provider inference | 已有但不足 | `ModelProvider.stream` 和 `ModelGateway` 有稳定边界；Provider request 没有 execution-level overall deadline，正常路径依赖 transport。 |
| Provider streaming | 缺失 | Provider adapter 通过 `AsyncThrowingStream` pump 转换事件；没有 stream idle watchdog，stream source 长时间不产出时 Agent 可能持续等待。 |
| Provider transport | 已有但不足 | `URLSessionProviderHTTPTransport` 使用 `URLSession.bytes(for:)`，只在 stream termination 时取消 pump/bytes task；没有统一 connection/overall/idle 分类。 |
| Builtin Tool | 已有但不足 | `ToolRuntime` 有参数、权限和错误归一化，但没有外层 deadline；filesystem 读写直接执行，不能由 Runtime 统一取消。 |
| Read / search | 已有但不足 | `grep`/`glob` 通过 `runToolProcess` 有约 30 秒局部限制；`read_file`/目录读取没有统一 deadline。超时后没有统一 typed deadline diagnostics。 |
| Mutation Tool | 已有但不足 | `edit_file`/`write_file`/`apply_patch` 有事务或内容检查，但没有 Runtime deadline；超时后没有 `executionStateUnknown` 语义。 |
| Foreground Shell / Git | 已有但不足 | shell/git 使用 `runToolProcess`，默认约 60 秒；`Process.terminate()` 只处理直接子进程，没有 process group、grace/force kill、bounded cleanup。 |
| Background Process | 已有但不足 | `ProcessTool` 的 `start/poll/input/stop` 能立即返回 handle；没有 maximum lifetime、owner lifecycle 和 Core shutdown 等待，`ToolProcessStore` 也不回收自然结束的条目。 |
| MCP request | 已有但不足 | HTTP request 设置 `timeoutInterval`；stdio 使用 `runToolProcess`；`tools/call`、`tools/list`、GET 等没有统一 request deadline/cancellation correlation。 |
| MCP health | 缺失 | `MCPConnectionManager` 只有 invoker registry/call，没有 healthy/degraded/unavailable 诊断状态或 bounded shutdown。 |
| Subagent | 已有但不足 | `runChild` 只有 profile 显式 `timeoutSeconds` 时启动 race；默认无 timeout，child deadline 不会 clamp 到 parent remaining。 |
| Cancellation | 已有但不足 | Permission/Question 使用 `withTaskCancellationHandler`；Provider pump 和 process 有局部 cancellation；root 到全部 owned execution 的 tree 没有统一注册与清理确认。 |
| Clock | 已有但不足 | 运行耗时部分使用 `ContinuousClock`，但 MCP lease、Subagent profile 和测试轮询仍使用 `Date`；没有 scenario-local deterministic clock seam。 |
| Configuration | 已有但不足 | `RuntimeSettings.commandTimeoutSeconds` 已编码但运行时没有统一读取；没有按 execution category 的 default/maximum/validation。 |
| Persistence | 已有且足够（对既有 terminal 状态） | `AgentRunStatus.timedOut` 已存在，terminal run/result 可原子保存；恢复会把非 terminal run 标记 `recoveryRequired`。Tool timeout diagnostics 和 unknown-state 字段尚未存在。 |
| Protocol | 已有但不足 | `ToolOutcome` 已包含 `timedOut`/`cancelled`，`AgentRunStatus` 已包含 `timedOut`；缺少 `transportLost`、`executionStateUnknown` 和统一 diagnostics 表达。 |

## 分类说明

### 已有且足够

- Tool 参数校验、权限边界、敏感路径防护。
- SSE 分帧和 Provider terminal 校验。
- Tool batch 并行执行以及 SQLite terminal persistence 的基本原子性。
- Permission/Question 对迟到回复的拒绝。

### 已有但不足

- 局部 shell/MCP timeout、`URLRequest.timeoutInterval`、process termination、provider stream pump cancellation。
- AgentRun/ToolResult 的部分 terminal 状态。
- `ContinuousClock` 在若干性能计时路径中的使用。

### 缺失

- Core 统一 `ExecutionDeadlinePolicy`、effective timeout 和 deadline inheritance。
- overall/idle/cancellation 的统一分类与 typed diagnostics。
- Provider streaming watchdog、MCP request watchdog、Tool 外层 watchdog。
- mutation timeout 的 known/unknown state；process group cleanup 和 bounded termination。
- background process owner lifetime、Agent shutdown 的统一 cleanup。
- scenario-local deterministic clock/test watchdog。

### 后续阶段

- timeout 后 retry、Provider fallback、换模型、重新 spawn child。
- Agent planning、prompt、routing strategy、workflow、GUI、remote runtime、新 Provider。
- MCP 自动 failover/reconnect 和复杂 scheduler。

## P15.1 接入边界

1. Runtime policy 提供 category default/max；调用点只提交请求 timeout；parent deadline 负责 clamp。
2. `ExecutionDeadline` 使用 `ContinuousClock` 的 monotonic instant；wall clock 只用于展示和既有持久化时间戳。
3. Tool/Provider/MCP/Subagent 在 Core 边界返回既有 typed result 或 terminal error；不在 Runtime 内 retry。
4. mutation 在 timeout/cancel 后不能伪装成确定失败；需要明确 `executionStateUnknown` 与 verification-required diagnostics。
5. background process 由 handle/lifecycle 管理，不用无限 foreground timeout。
